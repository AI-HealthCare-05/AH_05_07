## 실제 제작과 검사 범위

현재 선택 자산은 `bear-v007`, `rabbit-v002`, `dog-v001`, `cat-v002`,
`red_panda-v003`, `otter-v003`, `capybara-v002`, `penguin-v002`,
`squirrel-v001`, `hedgehog-v004`, `fox-v002`이다. 첫 두 종의 생성
커밋은 `98752a3996cf1844783a9d250bd88761b2be1e70`, 강아지는
`146b45aa8b5963efe63adcc6afc8daa2721b3761`, 고양이는
`c7c41323318f0af4159be29d04bdc3c0c3837e53`이다. 제작 소스 변경 뒤 이전
manifest의 commit이나 해시를 수정하지 않는다. 카탈로그의 기준 main,
실제 생성 커밋, 뷰어 실행 커밋, 후속 문서 커밋을 구분한다.

각 종은 편집 원본, 20개 bone rig, 실제 7개 skeletal clip, 표준/경량 GLB,
네 방향 표준형 1600×1800 RGBA 렌더와 전체 동작의 선택 포즈를 가진다.
표준형과 경량형을 동작 수에 중복 합산하지 않는다. 개별 생성 manifest는
생성 직후의 QA 대기 상태를 보존하며, 후속 기술 판정은 별도 검토 sidecar와
카탈로그에 기록한다. 파일 목록 도구가 품질 통과를 추론하지 않는다.

- 독립 바이너리 파서와 새 Blender GLB import에서 실제 skin/clip/원본 해시,
  7개 동작별 13시점의 유한 변형, loop endpoints와 프레이밍을 검사했다.
- 선별 정적 렌더와 양쪽 버전의 실제 Chromium 전체 7개 동작 재생을 확인했다.
  고정 바닥 추가 검토는 move/special/celebrate의 정면/측면 재생 및
  25%·50%·75% 자세를 확인한다. 바닥은 표준형 기본 자세에서 한 번 고정한다.
- 저장 영상 전체 decode·검은 구간 검사와 실제 추출 frame을 검토했다.
  의도한 수직 bounce는 in-place hop이며 발이 항상 붙은 보행으로 설명하지 않는다.
- 이 검사는 모든 프레임의 물리 충돌·발 고정, 사람 디자인 승인 또는 운영 적용을
  보증하지 않는다. 실제 모바일 기기 대신 1366/390/320 브라우저 viewport를 썼다.

고양이 v002는 귀/눈 부착 수정 뒤 정적·브라우저·바닥·영상 검토를 통과했다.
선택한 열한 종의 편집 원본 22개도 각각 새 Blender 세션에서 정상적으로 열렸으며
rigged의 20개 bone/skin과 source의 7개 action/keyframe, 원본 해시 불변을 확인했다.
레서판다와 수달 v001은 실제 렌더의 볼/가슴 무늬 경계 결함으로 추가 렌더를
중단해 보존했다. 레서판다 꼬리 띠의 계단 경계도 수정했다. 실제 피부 면에 재질
경계를 넣은 v002는 경량화가 일부 기존 정점의 뼈 영향을 다섯 개로 합쳐 엄격한
네 개 제한 검사에서 중단됐다. 이 두 build 실패를 보존했고 audit/render로
넘어가지 않았다. 감면 직후 해당 정점만 상위 네 영향으로 정리하는 수정은
원본을 저장하지 않는 Blender 메모리 재현에서 통과했다. 기존 정상 가중치와
경계 검사 조건을 유지했다. 이후 새 후보의 실제 내보내기·변형·재생은 별도 실행에서
검토했으며 수정 소스 검사만으로 완료 처리하지 않았다.

카피바라 v001은 binary 검사와 표적 렌더 명령이 통과했으나, 정면에서 작은 귀와
낮춘 두상 사이의 틈을 확인해 완료 수량에서 제외했다. 새 귀 위치/회전 중심,
별도 주둥이·콧구멍과 외부 꼬리 제외를 구현했다. 실패한 기존 후보에는 추가
전체/경량 렌더를 수행하지 않았다. 새 `red_panda-v003`, `otter-v003`,
`capybara-v002`는 `6a617adff19252d6883db869c89c2fdfdd8d30c1`에서
18개 제작/검사 단계를 모두 통과했다. 실제 PNG 72장을 검토하고 66장을 선택했으며
검사 맥락을 포함한 147개 사본의 크기/해시를 대조했다. 세 후보는 viewer
`2033c366e742645cb31f642b7b4a8a44fc7e1257`에서 각각 전체14개 variant loop,
고정 바닥12개 view-variant loop/36개 자세와 원본 열기를 통과했다. 추가 근접8개
loop, 무음 영상8개 전체 decode 및 명시한 이미지 표본을 검토한 뒤 선택했다.
실행 기록의 실제326개 파일 참조/해시도 독립 대조했다. 이 결과의 문서 반영
커밋은 `b28596c3e2ac8390364621c49d38a3983ea497ec`이며 실제 실행 SHA와 구분한다.

레서판다 꼬리의 작은 normal 방향 진단은 표준2개/경량1개 면에 남는다. 결합한
재질 경계 topology는 닫혔고 검토한 연결부에 큰 결함은 보이지 않았지만, 작은 면의
접힘·자기 교차 또는 모든 프레임 충돌을 배제한 것은 아니다. 실제 카메라에서
subpixel 크기로 계산됐다는 이유만으로 무해하다고 판정하지 않는다. 수달의 손
방향 변화와 카피바라의 고개·귀 부착도 관찰한 시점에 한정하며 정확한 물리 접촉은
보증하지 않는다. 당시 7종 보관 목록과 manifest는 보존했다. 현재
`selected-inventory-eleven-001.json`과 `manifest-checkpoint-eleven-001.json`이
11종/77개 고유 동작과 후보별 후속 sidecar를 연결한다. 352개 선정 파일
479,157,979bytes에 원본·GLB·242개 선별 PNG·22개 진단 WebM이 포함되며
필수 파일 누락은 없다. 표준/경량을 별도 동물이나 고유 동작으로 세지 않는다.

다음 제작 전 여우의 실제 앉기 포즈에서 바닥 침범을 확인했다. 두 발을 root 기준으로
고정하는 수정은 새 Blender의 193개 정수/반 프레임 표본에서 접점 검사를 통과했고,
다른 여섯 동작의 원래 키 자세를 재현했다. 이동 동작의 키 사이에는 최대 약
0.0001241 단위의 발 위치 차이가 있어 완전히 같은 보간으로 표현하지 않는다.
물범은 몸체 변형이 root 축까지 기울이는 코드 결함을 수정했고, 새 Blender의
7개 동작 × 97프레임에서 수평 root 이동 없이 기존 수직 크기와 루프를 확인했다.
이는 원본의 좁은 변형 검사이며 새 여우/물범 자산의 시각 품질 통과가 아니다.
`0c5ccbf988b00540fedb65adc79fec1683a717bf`의 다음 제작 묶음은 세 상태로
마감했다. 고슴도치 v001은 가시 태그 읽기에서 build exit1로 중단했다. 펭귄 v001은
binary/표적 렌더를 통과했으나 공통 포유류 주둥이·웃음선·공꼬리가 남아 형태 수정을
위해 전체 렌더를 보류했다. 물범 v001은6개 제작/검사 단계와 정적24장 검토를
통과했고22장/49개 사본을 보존했다. 전체11단계 중10개 exit0·1개 exit1이며,
어느 후보도 이 제작 묶음만으로 최종 통과 수량에 추가하지 않았다.

고슴도치의 실제 단일 가시 메모리 진단에서 Blender SUBSURF 뒤 태그 값은 남았지만
보관 RNA 그룹 참조의 인덱스가 `-1`로 바뀌는 것을 확인했다. modifier 뒤 그룹을
이름으로 다시 조회하는 수정은 같은 probe에서 태그 전달·부착·임시 그룹 삭제를
통과했다. 진단 명령의 exit0은 원래 attachment 실패를 포착했다는 뜻이며 원래
build 성공이 아니다. 수정 검사에서도 기저 존재·0.5 기준·삽입 깊이는 그대로다.
이후 이마 가시 배치의 실제 build는 기존 높이 guard에서 중단됐다. 순수 fixture가
기하와 함께 태그까지 평활화해 native의 선형 태그 전달을 재현하지 못한 원인을
확인했다. fixture 수정으로 같은 두 가시의 실패를 재현한 뒤 이마 기저를 0.04
낮췄으며 기존 guard를 유지한 native 77개 부착 검사가 모두 통과했다. 이 좁은
메모리 수리 검사 뒤 별도 v004를 실제 생성·렌더·브라우저에서 검토했다.

남긴다. 전체 영상 decode와 표본 열람은 모든 프레임 관찰을 뜻하지 않는다.
보존한 진단 영상에는 조작 중 스크롤·일부 잘림·종료 회색 여백이 있어 최종 발표용
편집 영상으로 표시하지 않는다. 영상 사본8개를 재인코딩 없이 검토 당시 해시와
대조해 추가했고, 원본·hero·영상·QA 참조를 포장 전후 검증했다. 이전 catalog의
바이트도 별도 snapshot에 보존했으며 과거 검토 JSON의 해시를 새 값으로 고치지 않았다.

물범 v001은 자동 검사 뒤 실제 박수에서 지느러미가 떨어져 있는 결함을 확인했다.
제한된 동작 진단에 이어 단일 구조 수정안도 몸통·지느러미 교차로 실패해 미채택했다.
진단 exit0을 품질 통과로 해석하지 않으며, 같은 방식의 추가 탐색은 중단했다.
물범은 `needs_revision`으로 GLB 선택과 완료 수량에서 제외한다. 수동 형태·리깅
수정과 전체 변형 검토가 필요한 기술 차단이며 외부 승인 문제로 바꾸지 않는다.
이전 실패 원본·렌더·검사와 미채택 소스를 보존했다. **12종/84클립 완료가 아니며
모든 후보의 사람 디자인 검토도 대기**다.

G4 실제 생성 소스 `7d9d97ee520bebe73556cf9787a4eea2de73d327`에서 순수 검사
106개와 Ruff lint/format, Windows/Linux를 포함한 CI 17개가 통과했다. 이전
`0c5ccbf`의 88개 검사 기록도 보존하며 새 후보의 성공 근거로 바꾸지 않는다.
G5 문서 반영 `b28596c3e2ac8390364621c49d38a3983ea497ec`의 CI 6개도 통과했다.
앞선 Windows 영상 종료 시간 초과는 실패로 보존했다. 전체 14개 variant loop의
기능 검사는 유지하고 별도 한 합성 clip의 전체 루프 녹화·종료 검사를 분리했다.
CI는 합성/계약 검증이며 비공개 로컬 제작물을 다시 렌더하지 않는다.
다섯 브랜치를 합친 별도 checkout에서 실제 web build와 운영 번들 경계를 검사했고,
G4 `7d9d97e`와 G5 `b28596c`까지 포함한 통합 문서의 상대 파일 링크128개와
보호된 소스 범위를 대조했다. 이후 소스 통합 검사는 별도 기록한다.
원래 사용자 worktree나 운영 환경에 이 통합 checkout을 적용하지 않았다.

## 제작·보관 경계

- 로컬 실행 폴더에는 실행 상태, 재개 지침, 실패 기록, 파일 크기·SHA-256·도구
  버전·생성 소스·검증 범위를 기록한다. 원본·GLB·렌더·영상은 외부 로컬 폴더에
  둔다. 저장소에는 제작 소스와 작은 계약·검사 기록만 반영한다.
- Blender 4.5.13 LTS Windows portable을 공식 배포처에서 받아 공식 SHA-256과
  대조했다. 관리자 설치나 기존 Python/Node/프로젝트 lock 업그레이드는 없다.
- 내장 이미지 생성의 곰 시안은 제작 참고용이다. 사용자 이미지 승인 기록은
  없으며, 이미지 시안을 3D 완성 자산으로 세지 않는다. 유료 3D 생성은 사용하지 않는다.
- 모델링·리깅·내보내기 단계마다 원본을 저장하고 실패 버전을 보존한다.
  곰 첫 버전의 팔 가중치 결함은 실제 포즈 렌더에서 발견했으며 수정 전 결과는
  품질 통과 수량에서 제외한다.
- 같은 디스크의 checkpoint는 독립 백업이 아니다. 승인된 별도 백업 위치와
  외부 자산 업로드 대상은 아직 없으므로 독립 백업·외부 공개를 주장하지 않는다.
