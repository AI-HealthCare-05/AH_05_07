# SK7 모델 출시 준비 판정 계약 초안

Issue #221. PR #220 병합 `64aca180aab940a731c322fcf22693a5ec58d756`을 기준으로
현재 validation 결과를 **이미 본 뒤** 작성한 계약이다. 기존 결과를 보기 전에
정한 기준이라고 주장하지 않는다. 이번 PR의 문서 승인과 모델 선택·test 실행·
직렬화·운영 출시 승인은 각각 별도다. 새 수치 통과선을 만들지 않는다.

## 완료 범위와 판정 의미

- #217: #218 병합 및 Windows/Linux 합성 CI로 구현 범위 완료·종료.
- #219: #220 병합, 승인 JSON 원본 보존과 Windows/Linux verifier CI로 증거 공개
  범위 완료·종료. 두 종료 모두 전체 모델 검증·출시 완료를 뜻하지 않는다.
- 데이터 준비, 실제 비교, 탐색적 불확실성의 승인 집계는 저장소에 존재한다.
  현재 모델 상태는 `exploratory_uncertainty_not_promoted`다.
- **충족**은 표의 한정된 조건에 증거가 있다는 뜻, **미충족**은 필요한 산출물이나
  검증이 없다는 뜻, **미정**은 판단 기준/지원 범위/승인자가 확정되지 않았다는
  뜻이다. 충족 항목 개수로 종합 출시를 승인하지 않는다.

아래 승인 주체는 필요한 역할이며 실제 담당자 지정이나 서명을 대신하지 않는다.
프로젝트 책임자(사용자)가 역할별 책임 있는 검토자를 지정해야 한다. 미지정·미서명은
승인이 없는 상태다. 데이터/ML 담당자는 증거를 작성하고, 독립 통계 검토자는
방법과 불확실성을, 분야 안전성 검토자는 오탐·미탐의 사용상 영향을, 제품/UX
담당자는 대상·문구·사용 맥락을 검토한다. 운영 책임자는 운영 승인에 별도 서명한다.

기존 validation은 이미 관측했으므로 이후 선택·설계의 영향을 공개한다.

## 향후 test: 고정 후 별도 승인된 한 번의 평가

1. 데이터 접근 없이 실행 계획을 작성한다. 지원 대상·라벨·8feature 의미·질문/
   adapter 버전, 선택 모델 및 고정 fit/재현 절차, 전처리(결측 통계 포함),
   calibration 유무/방식, signal_band 임계값, 모든 CONFIG/lock/commit과 frozen
   partition 역할을 식별한다. 최종 fit은 test 이전 별도 승인 작업으로 고정하며,
   test 평가 후 재학습한 다른 모델에 결과를 재사용하지 않는다.
2. 평가 지표(전체 AUROC/AP/Brier, calibration, 성별/연령 및 승인 대상 subgroup),
   bin/불확실성 방식, 작은/빈/단일 클래스 처리, 표본 충분성, 공개 allowlist,
   기준값 또는 판단 규칙의 근거, 실패·산출 불가·표본 부족 시 조치를 명시한다.
   현재 bootstrap 계약을 test에 자동 적용하지 않는다. test 목적의 구간/다중
   비교 규칙은 검토자가 별도로 확정해야 하며 현재 미정이다.
3. 선택 모델·전처리·임계값·지표·판정/실패 조치와 provenance를 변경 불가한
   사전 고정 패키지로 commit하고, 통계/분야 검토자 및 사용자의 별도 실행
   승인을 기록한다. 미정 항목·미서명 항목이 있으면 test는 열거나 해시하지 않는다.
   고정된 기존 metadata 참조는 계획 단계에서 사용할 수 있다.
4. 승인된 실행자만 기존 held-out test를 한 번 평가한다. 이때 처음 수행할 입력
   해시/스키마 확인, 예측, 집계 검증 및 접근 기록 절차를 패키지에 포함한다.
   개별 데이터·예측·모델은 공개하지 않는다. 집계 검증과 사람 품질 판단을 분리한다.
5. 결과가 불리하거나 부족하면 출시 보류·범위 제한 검토로 종료한다. test 수치에
   맞춰 모델/보정/임계값/통과선을 바꾸지 않는다. 같은 test를 다시 사용해 선택
   모델의 반복 승인 근거를 만들지 않는다. 변경이 필요하면 기존 test를 이미 본
   평가 자료로 표시하고 새 독립 평가 자료와 별도 설계를 확보한다.
6. 기술 실패도 성공으로 처리하거나 자동 재시도하지 않는다. 안전한 실패 기록을
   보존하고 test가 노출됐는지 독립 검토한다. 재접근/재실행을 이 계약이 자동
   승인하지 않는다. 결과 노출 시 같은 test로 튜닝·재승인하는 경로는 금지한다.

이 절차는 test 실행 명령이나 운영 승인이 아니다. Test 결과 한 번이 통과하더라도
외부/한국 검증·입력 계약·운영 승인 등 다른 미충족 조건을 대체하지 않는다.

## 보정 실험이 필요할 때의 후속 설계 조건

이번에는 보정을 실행하지 않는다. 이후 계획은 최소한 **학습**(모델·전처리 fit),
**보정**(고정 모델의 확률 변환 fit), **선택**(보정/모델/임계값 비교),
**최종 평가**(잠근 test 또는 새 외부 평가)의 역할과 행별 겹침을 명시해야 한다.
같은 행을 보정 fit과 보정 성능의 독립 평가로 사용하지 않는다. Train 내부
분할이나 cross-fitting을 택한다면 fold/seed, out-of-fold 예측 생성, 전처리 fit
범위, 최종 fit·선택 절차를 사전에 고정한다. 기존 validation을 선택에 다시 쓰면
이미 관측한 선택 자료임을 공개하며 새 독립 평가처럼 취급하지 않는다.
Test를 보정/선택에 사용하거나 새 역할 분할을 이번 작업에서 만들지 않는다.
방식·데이터량·표본 적정성과 누수 방지는 통계 검토자 승인 후 별도 실행한다.

## 향후 artifact·metadata·반복 입력 계약

현재 [metadata scaffold](../app/core/model_artifact.py)는 model_version,
split_digest, features, artifact_sha256만 가진다. [직렬화 scaffold](../scripts/model/train_artifact.py)의
존재는 승인된 artifact가 있음을 뜻하지 않으며 그 명령을 출시 절차로 사용하지
않는다. 다음 필드를 요구하는 확장 명세/검증은 후속 구현 전 검토해야 한다.

- 모델 종류·fit/실행 commit·학습 provenance, lock/CONFIG digest 및 artifact hash.
- 정확한 feature 순서·semantics/questionnaire/adapter 버전·단위·범주/결측 규칙,
  fitted 전처리 식별과 hash. 개별 fill values는 공개 metadata/로그에 넣지 않는다.
- signal_band 임계값·확률 해석·calibration 여부/버전, 선택/평가 evidence 참조,
  지원/제외 대상, 승인 주체·승인 범위·일자와 모델 버전의 연결.
- 같은 정규화 입력·동일 artifact/환경에서 같은 확률·band·버전이 나오는 합성
  반복 검증과 API 통합 증거. 수치 허용오차는 실행 환경 근거로 후속 명세에서
  먼저 고정한다. 값 반복성은 품질의 충분성과 별도다.
- hash·feature/semantics·CONFIG·임계값 불일치, 미지원/누락 입력, 미승인 artifact에서
  점수 없이 차단하는 검증. artifact 환경 변수만으로 route를 활성화하지 않는다.

[모델 카드](model-card.md)와 [입력 adapter 초안](model-input-adapter-contract.md)은
이 판정의 근거 문서다. 현재 실제 adapter·artifact·성공 API·모델 운영은 활성화하지
않고 기존 503 model_not_ready 및 no-score 동작을 유지한다.
