# ADR-0004 — Bounded frozen validation comparison

Status: proposed under Issue #213; accepted after user merge. Extends ADR-0003.

The former baseline script omitted calibration/subgroups and hash provenance;
the standalone evaluator silently omitted single-class subgroups. Replace that
execution path with one validated comparison CLI and reusable aggregate report
functions. Keep the same two estimators and shared manifest-driven preprocessor,
existing libraries and lock. Freeze CONFIG version 1 and reporting/suppression
rules in the runbook before actual evaluation. No new dependency or service.

Both models receive the same frozen train/validation matrices; only train fits
preprocessing and models. Verify input byte identity against approved Gate 1B
and metadata semantics before fit. Never access test.parquet. Its trusted
Gate 1B digest remains an attestation rather than a recomputed comparison input.
Abort convergence/numerical warnings and invalid probabilities. Preserve failures
and refuse overwrites. Aggregate evidence binds execution/lock/split/config and
has a recursive allowlist. Public reporting requires separate human approval.

Alternatives: tuning or new models expands scope without evaluated need; using
test leaks selection information; separate free-form metric scripts allow rule
and input drift; dropping unsupported groups hides missing evidence. Null with
enumerated reasons and fixed small-group suppression makes limitations explicit.

Compute is bounded to two fits, fixed iterations and one native thread. Existing
pandas, scikit-learn and numeric dependencies retain their licenses and roles.
No paid service, production configuration or data download is added. Fitted
objects stay in process memory; no serialization or promotion occurs. Rollback
reverts this code while preserving local inputs/results; it must not republish
old outputs as if generated by a new execution commit. Future rule changes
require a reviewed version revision and new evaluation, not patched metrics.
